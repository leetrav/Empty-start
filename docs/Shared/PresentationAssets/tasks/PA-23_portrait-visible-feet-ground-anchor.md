## 已经实现的功能
当前立绘在更换姿态后有浮空问题：不同PNG可见内容大小与透明留白不一致。opponent_tier_portrait.gd现有visible_anchor_ratio初值(0.5,0.5)，PA-14另有body_pivot，中心定位可能导致不同姿态可见脚底Y变化。

## 本次任务
1. 对实际主角及四位对手的idle、各阶段、受击/击败贴图，检查不同可见内容边界、透明留白与当前纹理缩放/裁切；使用Godot实际画面确认浮空发生在哪些姿态。
2. 确定角色在直播间内统一的**站立基线**（容器可用区域底部合理高度），优先把**立绘可见内容的脚底/最低支撑点**对齐至该基线，而不是用每张完整PNG画布中心定位。
3. 可采用统一可见轮廓边界+底部中点锚点、单姿态修正offset、按最大立绘宽高居中横轴再底部对齐等当前代码最少改动的方式；基于角色与姿态实际图片选择可靠实现，并保留必要的可调偏移。
4. 保持阶段翻牌、流汗、动画pivot、受击/击败演出与前景遮挡原有时序；图片宽度变化时仍居中、脚底不浮空，角色高度在主播区有一致视觉重心。
5. 制作真实Godot逐姿态切换截图或小视频（仓鼠主角及至少每位对手的典型姿态），逐一确认脚底基线与背景地面一致。

## 本卡验收标准（真实Godot）
- 不同姿态切换时角色可见脚底基本落在一致的站立线上，居中显示且不会突然向上漂浮。
- 主角及外星人、kiwi、青蛙、狐狸实际运行至少各一组换图核验；不同图尺寸/透明留白有实际对齐依据。
- 程序翻面/舞蹈/受击及击败演出无新增位置跳变，交付前后Godot截图/录像与最终anchor参数。

## Godot 开发环境
- Godot 4.7.2/GDScript，项目 Empty-start，Windows PC优先，1920×1080正式画布。
- Godot-MCP-Native负责真实工程操作，godot_mcp负责官方API参考。

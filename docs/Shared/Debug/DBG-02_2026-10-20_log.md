## 根因与修复

- `Sandbox._ready()` 的 Plan B 分支只隐藏 DEBUG 面板，没有调用 `bind_sandbox(self)`；F3 打开时只能看到独立预览状态。
- 现有 `Sandbox.debug_set_player_pk()` 经 HitResolution 写入；Plan B 使用外部 PK getter，实际所有者是 `PlanBBattleHost`，因此 PK 预设无法写回 Host。
- 正式 Plan B Sandbox 启动时还因 `PlanBBattleUI` 缺少 `tier_breakthrough_fading` 信号而中断。现已由 `StageArrowFx.fade_started` 在升档箭头真实淡出时转发该信号，Sandbox 可以继续完成初始化。

## 改动

- `scenes/sandbox/sandbox.gd`：初始化开始时绑定 DEBUG 面板；快照加入 Host 人口、三槽卡、冷却、对手状态与可用操作；Plan B PK 写入 Host 并回读确认；重开、直播数据、倾向、弹幕操作和对手发表开关返回真实执行状态。
- `systems/plan_b/battle/plan_b_battle_host.gd`：增加当前运行局的 PK 调试入口、对手主动发表开关和只读快照。PK 变化继续经过 `pk_changed`、BattleAttemptFlow、HitResolution、CombatStage 和正式 HUD；0% / 100% 沿用失败 / 矛盾结束信号。
- `ui/debug/debug_panel.gd`、`ui/debug/debug_panel.tscn`：按玩法切换状态区，显示 P/O/N、三张卡及冷却、对手 AI 状态；Plan B 普通棋子战斗禁用旧弹幕按钮；成功或失败提示按操作返回值和回读状态生成。
- `ui/plan_b/plan_b_battle_ui.gd`：声明并转发升档箭头淡出事实，恢复 Sandbox 与 Plan B HUD 的信号兼容。
- 更新 `docs/Shared/Debug/README.md`、`docs/Shared/README.md`，并新增 `known_traps.md` 的 KT-49。

## 当前能力

Plan B 正式 Sandbox 中，F3 能打开和关闭面板；面板读取 Host PK、正式 Tier、棋子人口、三槽卡、冷却和对手状态。PK 预设可驱动 Host、HUD 和 Tier；对手主动发表可暂停 / 恢复；重开沿用当前真实战斗流程。旧弹幕清屏只在旧普通战斗或矛盾阶段开放，Plan B 普通棋子战斗禁用该入口。

# LOAD-02 每次直播前统一加载画面

用户要求现有右下圆点／正在加载画面用于全部直播前。检查后确认四场普通直播均通过房间start_live→SceneRouter.goto_game进入，原路由仅较慢读取显示提示，暖缓存可能只有黑幕；失败／暂停重开则在原Sandbox同步重建，完全绕过加载层。

## 实现

- core/autoload/scene_router.gd：正式GAME_SCENE_PATH目标固定显示原提示，完全遮幕最少0.6秒；沿用原0.20秒淡出、0.25秒淡入。其他路由的短加载／片尾策略保留。
- 增加prepare_live_attempt(action: Callable) -> Error，用同一常驻层覆盖原场景的重建动作。请求锁定后阻断重复操作，旧画面盖住后同步执行返回bool的回调，随后暂停树保持0.6秒及揭幕，防止新尝试在黑幕下推进。
- scenes/sandbox/sandbox.gd：玩家失败与暂停重开接入该入口；原清理顺序提取为_restart_current_attempt_under_cover，仍只重建当前关，保留周目进度。F3 debug同步接口直接执行该原动作，不新增人为等待。
- 没有新增加载美术或重做UI，无战斗规则、概率、奖励或音乐素材修改。新接口与玩家重开的异步语义已同步Shared README。

## 验证

Godot4.7.2 Steam / Windows D3D12 Forward+ / RTX3050 Laptop，1280×720真实GUI。tests/integration/live_loading_smoke.tscn预载正式GAME PackedScene，四个关卡分别准备相应已完成前关记录，经真实房间start_live进入。全部四场暖缓存开播也有提示，正确进入对应关；重复start_live与goto_game被拒绝。

首场将真实Host PK置0，等待原失败演出完成后，真实鼠标点击正式失败重开按钮，再测试暂停菜单原重开回调。两种入口都经过同一提示层，每次只重建一次且Sandbox实例不变；重开后真实Host运行、失败面板关闭、树恢复。共六段加载，采样期间PK按每个HitResolution实例保持冻结，最终LIVE_LOADING_DONE failures=0 checked_covers=6。日志D:/src/playtest-20261020/live-loading-final.log，无ERROR/WARNING。提示完全不透明时的帧首采样跨度626/504/547/611/604/604ms，0.6秒最低计时由生产代码保证，采样因长帧会漏两端，测试允许100ms采样误差，不报告为逐帧精确600ms。

截图D:/src/playtest-20261020/live-loading-cover.png为真实1280×720加载层，已查看且与用户指定样式一致。测试没有人工从第一关打到第四关，不冒充自然通关或冷加载性能结果。未验证其他设备、导出包、原场景回调失效故障注入及F3完整面板操作；F3同步方法通过代码保留。

初次夹具在失败演出尚未结束时就检查失败按钮，以及帧首采样过严，出现3项失败；已改为等待原演出完成，最终上述通过日志单列，不将旧日志当成功证据。

原global_loading_smoke真实GUI回归GLOBAL_LOADING_DONE failures=0，涵盖普通路由、重复请求、暂停重载、结局快照与错误恢复。日志D:/src/playtest-20261020/live-loading-global-regression.log中缺失路径／空PackedScene／TEST_ONLY_invalid_packed_scene报错为夹具故意注入的恢复用例，不宣称该日志完全无ERROR；正常流程无额外脚本错误。

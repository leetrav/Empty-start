## 给 A 的最短绑定与保存交接

以下是组合方调用顺序，未改 A 的独占文件：

1. 创建一次目录并 `load_production_tables()`；普通生成开始前 `traits.bind(area,catalog)`。Area 已有 `BattleAttemptFlow._start_attempt()` 调用 `begin_combat_attempt()`，CombatStage 已绑定正式首次技能数；使用 Area 普通批次派发时不要再对同一时机调用 Runtime 显式技能生成。
2. HintView 先入树 ready，再 `hint_view.bind_runner(tutorial)`，且应在 `tutorial.begin()` 前绑定。
3. 默认同步连接 `battle_flow.shot_resolved` 到 `traits.on_shot_resolved` 和 `tutorial.on_shot_resolved`。分裂读取 Flow 已结束但尚未析构的同帧源，不能用 deferred 连接。
4. 监听 **attempt_started 一次**：`traits.begin_attempt(level)`；`hint_view.clear_hint()`；`tutorial.begin(level.tutorial_config_id, completed_step_ids)`。真实 Flow 重开同时发 attempt_started 与 attempt_restarted，因此同一重建逻辑不要重复绑定两者。
5. 仅普通战斗活动且教学场景适用时，每帧 `tutorial.observe_combat_frame(area,aim,attack)`。退出/切阶段时 clear_hint，场景释放时 traits.unbind；暂停沿用 SceneTree.paused，Observer和攻击均已防暂停推进。
6. `tutorial.step_completed(step_id)` 后从 `get_completed_step_ids()` 取完整副本交给周目存档拥有者。需保存的数据是**当前周目已完成步骤ID列表 `Array[String]`**（24表三个step_id），失败重开/恢复沿用，新周目清空；配置ID读取 `LevelProfile.tutorial_config_id`，无需存另一份 active_index、提示或蓄力。
7. 截至本次main，SaveData没有已落地的教程完成字段/API。由 A 在其拥有的 INT-16 存档工作中落实字段和序列化，本 Lane 没有伪造既存写入接口。示例变量 `completed_step_ids` 表示该保存列表，不代表已有 SaveData 属性。
8. 视图晚绑定到已进行的 Runner 时，读 `get_current_hint()`，非空则调用 D 的 `show_hint(step_id,hint_text)`；常规 bind-before-begin 会直接收到信号。全部完成时 Runner 已发 tutorial_completed，D 自动隐藏。

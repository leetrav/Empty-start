# INT-05 Windows UI／全屏与分辨率验收记录（2026-10-09）

## 结论

**部分通过，暂不签收整张 INT-05 卡。** 基于 `w7775p/main` 的 `359bebc7f14be38b7d2b1302ab16b360722a40e2`，R01～R04 均已在 Windows 图形窗口中打开主要入口；使用 INT-04 `TEST_ONLY` 夹具在九个精确窗口尺寸下走通 Rest、神降临和 Ending，其中 R01 的自动输入三次仅一次走通。全屏设置与暂停层在 R01 的真实窗口中切换成功。R05～R09 仅有程序生成的图形流程，没有完整人工交互；连续缩放与若干输入边界尚未实测，因此不能宣称全部验收通过。

### 测试环境与方法

- Godot `4.7.2.stable.steam.ed1daf0bf`，Windows `10.0.26200.0`，NVIDIA GeForce RTX 3050 Laptop GPU，图形运行日志为 OpenGL 3.3 Compatibility。
- 当前显示器报告的逻辑桌面为 1707×960，Windows DPI=144（150%）。未独立读取显示器物理原生尺寸；不将逻辑桌面尺寸误记为原生尺寸。单显示器环境，其他 DPI 与多显示器未测。
- 最新 main 的干净独立分支 `feature/int-05-windows-ui-qa`；没有改动用户位于 E: 的原工作副本，也没有改动上游 main。
- `project.godot` 使用 `canvas_items` / `expand`；Sandbox 设计列宽为左 448、中央 1024、右 448。
- 一组**真实可见窗口人工点击**：主菜单、设置、三步身份、房间、战斗、暂停；R01 还检查了全屏设置及暂停中切换全屏。对应 `Rxx_window_*.png`。
- 一组**图形模式自动流程**：复用现有 `tests/integration/int_04_full_run.tscn` 的临时测试副本，启动后强制窗口为目标尺寸，再跑现有 `TEST_ONLY` 流程并截图。临时副本没有纳入交付；窗口和根 Viewport 尺寸来自 `Rxx_test_only_stdout.txt`，截图为精确目标像素。`get_visible_rect()` 为 1152×648 设计坐标，并非窗口实际像素。测试存档隔离于项目的 `.godot` 目录。R06/R08 等大尺寸为隐藏图形窗口输出，未在实际对应显示器上做人工点击。
- `TEST_ONLY` 只验证布局与路线。占位句子、奖励、神谕等不代表正式内容；正式素材和参数的边界沿用 INT-04 记录。

## 缺陷与待查项

### INT05-01 — P1，1920×1080 图形自动输入偶发偏离

- **复现**：在 R01 窗口图形模式运行 INT-04 TEST_ONLY 流程三次，按现有脚本注入鼠标移动、蓄力、释放。
- **预期**：每次命中测试目标，普通攻击增 PK，随后矛盾结果一致，62 项全部通过。
- **实际／频率**：首轮报“普通真实攻击未增 PK／无历史”；第二轮报“真假结果错误”；第三轮 62/62 PASS。即 2/3 运行失败。前两次瞄准日志中 `viewport_mouse` 与预设目标坐标存在偏移；第三次调整窗口位置后通过。**这首先是自动输入与窗口定位的可靠性问题，尚不能判定为玩家真实鼠标的产品故障。**
- **证据**：`R01_test_only_stdout.txt`、`R01_test_only_stderr.txt`、`R01_test_only_retry2_stdout.txt`、`R01_test_only_retry2_stderr.txt`、`R01_test_only_pass_stdout.txt`。
- **建议**：检查 `Input.parse_input_event()` 注入时的窗口位置／Canvas 变换，增加窗口原点及鼠标局部坐标日志；随后在实际鼠标下复验 IN-02～IN-04。不要只凭一次自动 PASS 关闭此项。

### INT05-02 — P1，960×540 战斗细字可读性不足（人工观感，待复核阈值）

- **复现**：Windows 150% DPI 下以 960×540 窗口打开真实战斗画面，观察顶部 PK/Tier/阶段提示、两侧数据与底部蓄力说明。
- **预期**：任务卡要求主操作文字可辨认，重要战斗状态可读。
- **实际／频率**：一次人工检查中三列没有裁切，但上述文字和 ICON 明显很小；中央弹幕正文比 HUD 明显易读。尚无项目内最低字号标准，所以记录为 P1 可读性待修／待人工复核，不宣称功能失败。
- **证据**：`R04_window_battle.png`；对照 `R01_window_battle.png`。
- **建议**：为 960×540 设 HUD 最小字号／最小图标尺寸，并保留标题及操作提示的宽度；在设备上再次肉眼确认。

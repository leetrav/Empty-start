# PAUSE-03 PK界面触屏暂停入口

用户要求Android没有键盘时也能在PK页暂停。当前工作区继续承接既有本地优化，未读取／合并最新远端main，未推送或创建PR。

## 修改

ui/plan_b/plan_b_battle_ui.gd：在中央顶部PK栏右侧增加原生Button「暂停」，96×72逻辑像素，字号22，沿用既有主题。按钮与PK信息处于同一72px行内，PK信息横向缩小，棋盘及手牌设计高度不变。局部收紧PK面板／按钮的上下内边距，解决原主题最小高度78px撑过设计72px的问题。

新增pause_requested信号，scenes/sandbox/sandbox.gd连接到现有PauseMenu.pause_game，不复制菜单和暂停状态。按钮鼠标按下即暂停，避免长按按钮积累攻击；直接接受ScreenTouch并消费事件，不依赖触屏模拟鼠标。暂停沿用已有信号取消蓄力、冻结音乐与战斗，恢复／设置／Esc仍走原菜单。

## 实测

Godot4.7.2 Steam / Windows D3D12 Forward+ / RTX3050 Laptop，tests/integration/pk_touch_pause_smoke.tscn预载正式Sandbox，使用真实鼠标和InputEventScreenTouch输入分发。1280×720有效点击区域64×48像素；实际棋盘仍为(448,72,1024,828)，按钮与棋盘不交叠。鼠标打开原菜单、PK与BGM冻结、设置可点开、继续恢复，全部通过。

关闭Input.emulate_mouse_from_touch后，原生ScreenTouch仍打开原菜单，未蓄力／发射／发表；恢复后Esc仍打开／关闭同一菜单。2400×1080窗口在当前16:9内容黑边策略下，按钮可见且不覆盖棋盘；默认触屏模拟开启时仍只处理一次，继续后没有泄漏攻击／发表。PK_TOUCH_PAUSE_DONE failures=0，最终日志D:/src/playtest-20261020/pk-touch-pause-verified.log，无ERROR/WARNING。

初轮测试发现默认主题撑高到78px；已局部调整到72px并复验。宽屏测试最初使用窗口宽比换算事件坐标，忽略黑边，导致触点偏到立绘；改用Viewport.get_final_transform后通过。此为测试注入坐标修正，不是修改生产触摸偏移。官方依据：https://docs.godotengine.org/en/stable/classes/class_viewport.html#class-viewport-method-get-final-transform 。

实际截图pk-pause-720.png、pk-touch-paused.png均1280×720；宽屏截图pk-pause-20x9.png记录原宽屏窗口内容。已查看暂停按钮与菜单画面，无图像加工。测试准备开局身份后直接走正式路由，不冒充人工通关或APK运行。

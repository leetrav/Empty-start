# 2026-10-19 · 任务卡与执行流程（共同基线）

## 任务入口与优先级

- 唯一代码基线：[当前开发基线](当前开发基线_2026-10-19.md)，以后所有新代码任务从其**最新 HEAD**建立独立分支，PR 的 base 指向同一共同基线；`main` 由总控另行判断。
- 任务卡按 [`docs/Original/任务卡模板.md`](../Original/任务卡模板.md) 编写。需求优先顺序：**用户最新已确认变更 → 当前有效任务卡 → 当前可运行代码和系统正式文档 → 历史任务/PR**。旧实现记录只供追溯。
- 任务卡必须说清：任务编号与 Owner、直接依赖、当前已有功能、本次要做什么、验收结果和需交付的证据；每个要修改的文件确认唯一当前 Owner。
- 增量卡最新规格入口：[2026-10-19 新需求索引](2026-10-19_新需求与BUG开发任务卡索引.md)；其中 ID-16 覆盖 ID-15 滚动布局、PB-19 覆盖 PB-16 的128px头像和64px半径、PB-20 覆盖 PB-17 按人数变气泡宽度。

## 一张任务卡的最短执行链

1. **确认**：读取任务卡、仓库当前共同基线 HEAD、本任务直接相关文件和最新日志；确认 Owner 和已有修改。
2. **隔离**：从共享基线最新 HEAD 在 **D 盘**创建独立任务工作树；保护其他人的未提交改动。
3. **实现**：仅修改本任务必要代码及配置；不同子任务分别 commit，优先复用已存在的场景、接口和资源。
4. **验证**：逻辑任务只做一次直接相关的行为验证；视觉任务用真实 Godot 关键截图（分辨率、代码 SHA），动态效果按需一段短视频；不反复全项目测试。
5. **交付**：本任务代码、最小截图或日志、已知限制写入**同一功能 PR**（base 为共享基线）；证据不足保留 Draft。总控 Review 后决定是否合流，功能 PR 合流不代表 `main` 或发行验收。

## 项目存储目录

**不要在 C 盘存储项目数据**：代码副本及工作树、Godot 的 `.godot` 导入缓存、临时工程、运行日志、截图、录屏和打包产物统一存放在 D 盘（建议 `D:\Godot\`）；运行工具前确认其数据与缓存写入位置。

- 用户正在**另一个窗口**追溯阻断 BUG；本窗口不重复定位、不擅自修改该 BUG 的相关代码或其他工作树。
- **暂停 Windows/Android 打包和 GitHub Release 操作**，已有预发布保持不变，直至明确通知恢复。
- **不再向空闲 Agent 派发新任务**；已在做的任务自行收尾，待全部 Agent 空闲后统一核对交付、再决定下一阶段。
- 原旧 PR 保留追溯，不因共同基线已包含代码就重复 cherry-pick 或沿旧分支叠加新代码。

# PB-02 · Lane B · 观众棋子移动、碰撞感染与接触改口

日期：2026-10-17

分支：`codex/pb-02-planb-b-unit-contact-20261017`

## 本次完成

- 新建 `systems/plan_b/simulation/`，让每名观众由一个 `Area2D` 实例表示；位置、速度、阵营、当前完整话语快照、顺序、强度、特性、年龄、寿命和接触冷却均由该实例持有。
- 使用 Godot 原生 2D Area 重叠信号检测真实场景接触。碰撞后执行分离与反弹，再按中立 / 同阵营 / 同属性敌对 / 单向克制的顺序裁决。
- 完成游荡、追逐、逃避和边界反弹。默认速度范围 30–52 px/s、速度上限 78 px/s、侦测半径 220 px、追逐 / 逃避权重与速度倍率均可由 Inspector 调整。中立棋子直接游荡，活跃阵营棋子可追逐路人、追逐可克制敌人并躲避会克制自己的敌人。
- 强度仅决定合法感染概率：1 级 20%、2 级 35%、3 级 50%。同属性敌对接触只弹开；同阵营只弹开并把新 `word_order` 的完整话语快照传给旧棋子；成功感染完整复制传播者快照。感染失败保留受体状态。
- 默认创建 76 个中立棋子和 2 个额外中立播种位。A 将两个播种位用于对手初始棋子后，初始场上为 76 名中立观众和 2 名对手。总人口上限 96；有空位时每 0.75 秒新增一个中立观众。自然寿命均匀取 53–77 秒。
- 提供固定随机 seed、人口创建、场地配置、启动 / 暂停 / 清场、`seed_unit()`、阵营人数与只读棋子快照。碰撞类型表由外部注入，格式为“战斗属性 → 可克制的战斗属性”，B 不固定正式三角关系。
- 信号：`unit_changed(unit_id, reason)`（`seed/convert/relay`）、`unit_spawned(unit_id)`、`unit_despawned(unit_id)`；`contact_resolved(...)` 供定向验收使用。模拟不修改 PK。

## PB-01 / PB-04 接口交接

- A 在开始前设置 `set_play_area(rect)`，传入相对模拟节点的实际区域；场地、边界和碰撞均使用真实场景坐标。对 UI 返回的 `position` 是全局场景坐标。
- `create_population()` 默认返回 78 个中立 unit ID；A 从中读取两个播种位，调用 `seed_unit(neutral_unit_id, team, word_definition, word_order)`。棋子词语定义要求 `word_id/text/battle_type/tendency` 非空、`strength` 为 1–3、`traits` 为 Array。`team` 使用 `StringName`（`&"player"` / `&"opponent"`）。
- A 向 B 注入 `set_type_counter_map({"type_a": "type_b", ...})`；数据方向为键类型克制值类型。
- 查询入口：`get_faction_counts()`、`get_unit_snapshots()`、`get_unit_snapshot(unit_id)`、`get_neutral_unit_ids()`、`get_neutral_unit_at(global_position)`。单条查询返回空字典，位置未命中返回 `-1`。
- 启停入口：`start_simulation()` / `pause_simulation()`，并兼容 `set_active(bool)` 和 `clear_battle()`。物理帧由模拟节点自行推进，A 每帧读取人数快照更新 PK。
- 现有预制词接口没有指定独立“感染” trait ID；V0 将非中立阵营且持有话语快照的棋子视为可感染路人的一侧，中立棋子没有主动感染能力。新增数据若引入独立感染 trait，应由 A/C 明确注入规则后调整。
- PB-01 在自身 `start_battle(arena_size)` 中负责给 B 传入实际场地、注入 C 的克制表、创建人口、播种两名初始对手，再启动模拟。B 不提供 PK 或发表顺序管理。

### PB-03 费米分裂反击执行入口

- 新增 `apply_counterattack_effect(request) -> bool`，由 A 注入为 C `PlanBFermiOpponentDirector.set_counterattack_effect_handler()` 的执行器。
- 当前正式配置的原型请求格式为 `effect_id="split"`、`target_unit_id`（B 的 int ID 或十进制字符串）、`effect_parameters.child_count`。C 已确认 `alien_t3_split` 使用 `child_count=2`，字段与执行入口匹配。
- B 只接受运行中的有效对手棋子目标；在总人口上限内围绕目标生成指定数量的跟随者，完整复制 `team/word_id/text/word_order/battle_type/strength/traits/tendency`，给每个子体新的 `unit_id` 和独立寿命 / 速度，并发出 `unit_spawned`。满员或目标无效时返回 `false`；至少生成一个子体时返回 `true`。
- B 不改 PK；新增棋子计数会自然进入 A 下一次 `get_faction_counts()` 采样。前摇、反击冷却、最大次数和成功回报仍由 C 拥有；A 负责将效果请求转发给 B，并把 windup / resolved 事实转给 D。
- PB-02 直属烟测使用 C 相同 request shape 验证双子体、快照继承、`unit_spawned` 与人口上限。A 的正式场景接线由 A 的 `scenes/plan_b/` 与 `systems/plan_b/battle/` 文件所有者完成。

### 开局两个对手播种位

- `create_population()` 的 78 个对象全是中立棋子；A 在 `start_battle` 初始化期间选取两个返回 ID，以 C 提供的两份初始对手话语快照调用现有 `seed_unit()`，成功后阵营人数为 76 中立、2 对手。
- A 为每个成功初始化的起始话语分配全局 `word_order` 并写入本局已用词状态。此初始化属于开局状态装配，不消耗对手 11.5 秒的主动发言冷却；战斗开始后的玩家和费米主动发言继续走共享 `publish_word()`。
- B 已有的 `seed_unit()` 足以覆盖开局播种，无需新增专用初始化接口。若某个开局 seed 失败，A 应将初始化视为失败后再启动战斗，避免以 77/1 人数进入运行态。

## 验证结果

- Godot `4.7.2.stable.steam.ed1daf0bf`，D3D12 / Forward+ / AMD Radeon(TM) Graphics。
- Godot-MCP-Native 本机 `127.0.0.1:9080/cli/v1/doctor` 拒绝连接；使用已安装 Godot 官方文档 MCP 查询 `Area2D.area_entered`、`monitoring` 与 `RandomNumberGenerator.seed`。
- smoke 运行场景：`res://systems/plan_b/simulation/tests/plan_b_unit_simulation_smoke.tscn`。通过默认 76+2 人口、96 上限、A 查询入口、三种运动意图、边界反弹、快照深拷贝、同阵营传话、同属性敌我弹开、固定 seed 克制感染、中立感染、C 的 `split` request 执行、自然离场与补人检查；最终输出 `PB-02 PASS`，Godot 退出码 0，无本模块 GDScript 解析错误。
- smoke 另用 C 的反击 request shape 调用 `apply_counterattack_effect()`：`effect_id=split`、字符串 `target_unit_id`、`effect_parameters.child_count=2`。结果新增两个对手棋子，`unit_spawned` 各发出一次，两个子体继承当前话语快照；满人口时第二次应用返回 false。C 已确认该 request shape 与其导演输出一致。
- 96 棋子 D3D12 GUI 样本：180 个物理步墙钟间隔 2986.0 ms，平均每步 16.59 ms；Godot 当时报告 60 FPS。测量包含 smoke 场景预览和每帧快照读取，不是 CPU 独占剖析，也不能代表 Android 实机表现。

## 本次任务

### 1. 打通正式闭环与结算分支
- 从主菜单进入休息室；点击背景电脑打开菜单；“继续直播”进入 `scenes/sandbox/sandbox_plan_b.tscn`。
- 保留费米教学及现有战斗玩法。只修复闭环中能复现的信号断线、重复提交、空引用或场景路由问题，不调整玩法参数。
- 保留 main 中 #341 的结算双选：**继续直播**直接进入下一普通关，末关进入现有 DivineDescent；**暂时下播**保存同一份结算与下一关进度后返回休息室，再开播时恢复正确关卡。只修复可复现的残留断线，避免重写已合入路由。

### 2. 屏蔽圣典、图鉴与终结神谕候选阶段
- 休息室电脑菜单只保留“继续直播”；从 `rest_opening_room.tscn` 移除图鉴／圣典按钮及对应历史页实例，并清理其脚本引用、信号和回调。
- 结算页移除圣典／败者卡历史入口、历史子页、专属空态和相关奖励展示；保留本场直播结果、继续／下播操作及其必要状态。不要让已裁剪功能的空白提示占据结算界面。
- 保留矛盾判定、结果锁定、矛盾复读和现有过渡。成功击破并完成过渡后，**直接进入现有 Rest 结算**，跳过 `FinalOracle` 会话／候选展示／选择计时／候选攻击目标／确认回调。未击破路线继续沿用现有结算。
- 现有 `_open_rest_after_oracle()` 依赖已确认候选，不能原样调用。请在 `ContradictionOracleFlow` 中做最小成功交接：调用现有 `_commit_history_and_tendency()` 一次，创建 `RestSession`，使用现有 `breakthrough_oracle_complete` 结果类型，停止战斗并发出 `rest_ready`，由 Sandbox 现有 `_on_rest_ready()`／`_show_rest_result()` 展示结算。不得为此新增 Manager、Autoload 或另一套页面路由。
- 成功击破后不再新增圣典条目、败者卡奖励或依赖神谕确认的吞并奖励；普通命中历史与倾向累计仍按现有规则提交一次。保留 PK 结果、关卡进度、失败重开和继续／下播流程。旧存档及 `SaveData` 结构保持不变；不删除底层资源或历史数据。

### 3. 放大底部石头剪刀布话语卡
- 在正式 `PlanBBattleUI` 中放大 `WordHand` 面板和三张卡片。**单张话语卡的目标高度固定为 160px（Godot 逻辑像素）**，以 LD-17-FIX 调整评论区前 `LiveDataHud._create_comment_feed()` 的初始 `custom_minimum_size.y = 160.0` 为基准；评论区之后因粉丝横牌、多行正文或容器布局产生的实际高度变化，不得改变这项目标。这里对齐的是初始评论区的 160px 高度基准，不按当前评论区运行时高度动态拉伸。
- 卡片正文清晰度至少达到评论区设计字号（正文参考 20px）；同步放大标题、快捷键、强度／属性信息、图标和内边距。**三张卡上的石头／剪刀／布属性图标统一调整为 32×32px（Godot 逻辑像素）显示尺寸**，保持图标纵横比，不受原始贴图尺寸影响。三张卡保持统一高度，长句完整换行，不新增滚动容器、不用省略号掩盖字号问题。
- 保留三卡选择、1–3 热键、冷却填充、教程高亮及矛盾阶段切换。
- 三列宽度保持 448/1024/448，左右评论区不改。必要时调整中央棋盘可见高度及鼠标坐标映射，确保棋子不被遮挡、点击位置不偏移。1920×1080 与 1280×720 均需可读。

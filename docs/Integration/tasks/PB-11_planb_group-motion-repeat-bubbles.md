## 本次任务

### 1. 软结群、群体行动和接敌（Lane B）
1. 阵营棋子在原自主运动中加入**主动寻找同伴**：检测附近相同阵营棋子，互相靠近，在保留各自单位身份、原头像、碰撞和寿命的前提下保持适当间距，形成可观察的松散小队。
2. 小队成员呈现相近的运动方向与团体聚合感；参考简单的邻近吸引、间距分离和共享目标方向，按现有速度和位置系统实现最小局部转向，不另造复杂单位 AI。
3. 可感染的中立目标或可克制敌方进入侦测范围时，结群棋子主动接近并实际贴碰；遇到克制自身的威胁沿用回避。未发现优先目标时倾向向友军靠拢，而不是持续各自随机散走。
4. 同阵营靠近后仍是多颗独立棋子：接触时继续按 `word_order` 传递新话，**人数、PK计算和战斗棋子数量不因结群发生变化**。同阵营间软分离以形成贴近队形；敌对/中立实际接触按原感染、同类型、克制及碰撞冷却规则处理。
5. 让接触弹开在画面上持续一个短促可见的过程：保留接触后反冲速度/短时间击退状态，结束后再回到主动移动，避免下一物理帧重新计算转向直接覆盖。碰撞成功或失败都能看到“贴碰—弹走”。

### 2. 团体识别：决定哪些棋子共用一句话（B 提供快照，D 消费）
1. **气泡团体判定 = 同阵营＋同一当前 `word_id`＋空间上相连。** 附近成员以可配邻近距离组成连通集合；同阵营不同话语的棋子可相遇传话，但传话完成且满足邻近关系后才加入对应话语团体。
2. 每个团体提供唯一当前成员集合、当前原文、人数、成员屏幕位置及几何中心；1 人也视为团体。成员变化时刷新集合，团体距离拉远应自然拆开，后来靠拢应自然重组。
3. 使用简单邻域/连通关系与小幅距离缓冲维持稳定成员识别，避免接近阈值时每帧拆组重组导致气泡闪烁。尽量复用现有单位快照与事件，不创建额外复杂的持久“棋子合体”实体。
4. 不同话语、不同阵营的团体始终分别显示自身文本，气泡大小和尾巴只依据该团体当前成员。

### 3. 团体共享气泡：P1/P2、面积增长和尾巴（Lane D）
1. 一个团体同一时刻最多一个**共享复读气泡**；它放在当前成员几何中心上方，随团体移动，尾巴指向当前成员（不变成多个个人气泡）。
2. **单人 P1**：小椭圆或柔和圆角气泡，一条尾巴指向该棋子；**多人 P2**：主体横向展开、根据团体大小扩大，尾巴由其下缘指向若干成员，呈现“一群人齐声复读”的效果。
3. 团体尾巴按成员位置**抽样 2～5 条**，与人数和气泡宽度适配：1人1条，2人可2条，3人约2～3条，较大团体约4～5条；优先选横向分散的成员并连向真实位置，保持尾巴清晰。尾巴数量不会按8人就机械画8条。
4. **气泡尺寸由成员人数计算**，至少设置易调的 `bubble_size(group_count)` 或同等函数。P1 一人宽约100px、二人宽约150px、八人可放大到约500px是策划的**视觉参照点**，实际宽度按这些关键点插值并结合棋盘可见空间调整；泡体高度依据完整文本和字号自适应，不必将气泡等比例整体缩放。
5. 轮廓、底色、尾巴采用 **Godot 的 Control/_draw()/Polygon2D 或相应现有程序化绘制方式**，参考 P1/P2 画稿的粉色轮廓与简洁形状；保留能跟随阵营主题调整的配色。图片素材仍沿用棋子头像，本次不新增手绘气泡 PNG。
6. 团体数量变化时，当前气泡的宽度/尾巴锚点能平滑适配；位置靠近棋盘边缘时调整显示位置、尾巴指向和尺寸，保持完整文本及主体尽量在棋盘内。

### 4. 文本完整显示与字号/行高容器自适配（Lane D）
1. 气泡显示**该团体当前话语原文的完整句子**，不省略、不截断、不替换为摘要或省略号。
2. 采用容器字适应：根据气泡宽高与实际文本测量自动**缩小字号和行高/行间距**、智能换行，使完整文本在泡体内部排下；短句可用较大字号，长句自动缩小。真实文本需支持中文标点和不同长度。
3. 当缩小字号仍无法完整排下时，让气泡主体在可见范围内增加高度、调整换行与位置，优先保证整句话完整显示；长句不可由裁切、文字溢出或 `...` 解决。
4. 这些字号、行高、内边距、人数到宽度的映射为可配参数；必须以游戏已有 `03_普通词库` / 当前候选词的**最短及最长原句**现场验收，兼顾可读性与团体尺寸。

### 5. 团体级计时器与触发时机（B/D 接线）
1. **团体只有一个随机复读计时器**；随机间隔由统一可配范围抽取（建议初版2～6秒供美术验收）；计时到后整团显示一只共享气泡，显示时长可配（初版约1～2秒），结束后再次抽取随机间隔。
2. 以下事件优先**立即触发团体发声**：①玩家或对手发表话语、初始2/4/8棋子出生；②中立被感染第一次加入阵营；③棋子被敌方转化；④同阵营接触传话导致当前复读内容改变。事件对应气泡显示团体**最新当前完整话语**。
3. 初始批量生成或同一物理帧多人感染导致同一团体接连触发时，**合并为一次团体发声**，使刚出生的2/4/8颗信徒有立即说话的效果，而不是同一团弹出2/4/8只重叠气泡。
4. 一个团体成员改口、换阵营、退出或加入后，以更新后的同话成员集合和原文显示；团体合并/拆分时平滑转交计时状态，避免重复刷屏或因为不停重组永远不复读。
5. 优先显示事件触发气泡，普通随机复读按可配的同屏数量和优先级错峰显示；不同团体可同时发声，整体画面应看得清运动与感染。随机逻辑复用现有 RNG/固定 seed 测试入口。

### 6. 增量接线与最小验收
- **Lane B / `systems/plan_b/simulation/`**：只改自主移动与碰撞反冲，交付邻近同阵营吸引/松散集体运动和所需成员/事件公开快照。
- **Lane D / `ui/plan_b/`**：实现团体连通识别或消费 B 提供的团体快照、程序化气泡、尾巴抽样、全文本自动缩放、事件优先和团体随机计时。具体成员连通计算只保留一处真实来源，避免 B/D 重复维护。
- **Lane A**：沿用现有玩家/对手发表成功事实；若初始批量投放没有完整的 `word_published` 事件则作最小补线，传递出生批次的当前话语，配合 D 在团体结成时触发首句。
- **Lane E**：依赖实际 Godot 场景验收结群/接敌/回弹、团体复读可读性与 80～100 棋子的基础性能，记录真人可看的短视频和局部截图。
- 本卡不改变已完成的三卡独立刷新（若已接入）、2/4/8投放、感染率、阵营 PK、原对手技能及矛盾击破主流程。需保持当前可玩包直接正常运行。

## 本卡验收标准（实际 Godot 画面，真人验收）
1. 两颗同阵营棋子会主动靠近且保持独立，多颗同盟可形成移动小团体；与中立/可克制敌人接触后能看到**明显贴碰及弹走**；旧感染/接触传话不受影响。
2. **1人展示P1单尾小气泡；3人展示P2大气泡与2～3条尾巴；8人展示更大气泡与4～5条可辨尾巴**。尾巴指向实际成员，成员增减和位置变化时气泡同步变化。
3. 玩家一次发表初始2/4/8颗棋子后，能立刻看到这批信徒所在团体的**共享话语气泡**；中立感染、敌方转化、同盟改口都会显示新话语。
4. 不发生事件时，团体会按自己的随机计时重复说话；团体间不同步，团体内不会每人各弹一个气泡。
5. 较短和较长的真实中文话语**完整显示、不截断**，长话能自动缩字、缩行高、换行并按需增加气泡高度；棋盘边缘也能显示完整内容。
6. 80～100棋子真实运行时复读不淹没棋盘，游戏继续可操作；附运行中 **P1 / P2 / 8人团 / 长句自适配 / 改口 / 反弹** 的 Godot 实际截图或短录像、验证日志和对应任务完成日志。

- 目标：Windows PC 优先；1920×1080（中央战斗棋盘1024×828）；Android 后续复核缩放和触控显示。
- 工程操作：**Godot-MCP-Native**；官方 Godot API 文档：**godot_mcp**。

## 执行要求（仓库任务卡模板）

### 1. 先检查当前项目状态
确认目标 branch/worktree、未提交修改及最新 PR；查看 `project.godot`、相关场景真实 Tree、节点 Owner/信号、当前移动/碰撞/气泡 UI 和实际运行内容，然后最小修改。
### 2. 严格控制任务范围
只修改团体运动、碰撞反馈、团体识别和共享气泡的代码/配置/直接文档及最小测试，沿用现有主战斗流程。
### 3. 保持最小必要复杂度
优先在既有棋子模拟和 UI 中增加几项邻居权重、团体关联与绘制逻辑。使用现有 ID、快照与事件，完成后删去无用中间逻辑。
### 4. 组合优于继承
复用现有单位对象、UI 子组件、信号、Tween及原生绘图方法，通过组合提供团体视觉和运动行为。
### 5. 保持场景边界
B 维护棋子事实与运动，D 绘制群体气泡，A 协调发布和流程。跨模块采用稳定 ID、快照或信号。
### 6. 区分场景、逻辑和数据
当前话语以棋子快照为真相，团体由当前成员动态派生，气泡尺寸/节奏是表现参数，运行时计时归相关 UI/当前战斗生命周期维护。
### 7. 新增实现前按顺序检查
优先复用现有 Plan B 组件、Godot 原生 Control/绘图/字体测量、Tween 和随机数能力，再补足最小缺口。
### 8. Godot API 不允许猜
使用 `godot_mcp` 确认当前 Godot 版本的绘图、字体测量、文字换行、Control布局、物理帧等实际 API，按查询结果实现。
### 9. 使用 Godot-MCP-Native 检查真实工程
通过 Godot-MCP-Native 核对真实 Scene/运行节点和信号，运行并截取 P1/P2/8人和长句气泡的实机画面。
### 10. 自动化与额外保障机制
仅复用现有测试入口验证团体同话连通、随机计时、传话/感染更新与临界人数，视觉交真人实机验收。
### 11. 避免脆弱的 Godot 依赖
以 Unit ID、团体成员快照与 signal 驱动绘制，保持现有 Scene/Node 引用关系，不新增万能全局 Manager。
### 12. 修改现有场景时尊重现有结构
确认实例/继承、资源UID和节点 owner，沿用现有中央棋盘 UI 和背景，只增添对应动态视觉子节点。
### 13. 验证实际 Godot 行为
验 GDScript 解析、Scene/Resource加载、真实棋子运动/碰撞/感染、出生与改口事件、团体气泡绘制和一场正常战斗。
### 14. 完成前检查
核对同盟人数和 PK 数量未被结群修改、团体拆合不多发/漏发、文字始终完整显示、事件信号无重复绑定、无冗余 Scene/Resource/新测试设施。

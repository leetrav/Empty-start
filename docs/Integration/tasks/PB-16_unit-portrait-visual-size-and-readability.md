## 已经实现的功能
当前棋子实际显示极小，甚至小于周边文字，玩家无法识别头像。PR #271归档的六张原画均为**512×512 PNG**，游戏显示目标为128×128；当前模拟器默认碰撞半径为13px，本任务须按正式规格统一到64px。

## 本次任务
### 1. 视觉尺寸统一为128×128（D）
1. 所有中立、玩家和对手棋子在1024×828棋盘中显示为128×128逻辑像素；保持512×512原图比例、中心对齐和完整头像。
2. 倾向光圈、描边、受击反馈、团体气泡尾巴与选择提示按头像外沿重新定位，棋盘边缘保持完整可见。
3. 使用真实 Godot 截图记录场景与窗口分辨率，确认头像可辨认且没有拉伸。

### 2. 物理碰撞区域统一为128×128（B）
1. 棋子的接触、碰撞、阻挡、感染和结群使用128×128逻辑像素的有效范围；当前圆形模型设置为**半径64px**，与显示尺寸一致。
2. 同步核对邻域范围、空间网格、接触/感染、分离、边界限制、出生落点和点击反馈，确保模拟使用半径64px。
3. PB-15 开局30个中立棋子，A独立传入2个对手播种槽；玩家/对手按2/4/8成批投放。密度变化按真实人口及现有容量规则处理，保留完整批次语义。
4. 合流后做一次针对性真实场景验收，覆盖初始化、边界、接触感染、非接触和批次投放；记录容量或性能冲突，保持当前64px规则供负责人评审。

### 3. 截图验收（D/B/E）
1. 需要视觉验收的 PR 正文附真实 Godot 运行截图预览、分辨率与对应提交 SHA；动画可加短视频。截图展示30名中立与128×128棋子。
2. 画面改动附改前/改后对照；未提供真实截图的视觉类 PR 保持 Draft。
3. E 做一次与本卡直接相关的窗口验收及必要帧耗时观察；不重复容量 sweep。

## 本卡验收标准（真实 Godot）

- 30名中立开局及后续随机补人、整批2/4/8发表仍正常；头像完整可读且相邻棋子接触/感染与外观一致。

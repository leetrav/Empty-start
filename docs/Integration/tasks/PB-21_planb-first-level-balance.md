## 已经实现的功能
当前首关PlanB：PK从50%开始，Host的pk_rate_pp_per_second=0.85，按(P-O)/(P+O+N)变化；三卡独立5秒，S1/2/3生成2/4/8，感染率50/60/70%。首关敌方首发/后续约11.5秒、领先2人可能触发最多2次的临时分裂反击。旧模型为model_only旧参数，不能代表最新实机胜率。

## 原因分析与证据等级
**已从公式确认节奏偏慢风险**：如果P=8、O=2、N=30，则每秒仅0.85×6/40=0.1275百分点，50→100需约392秒（优势持续不变的理论值），超过2～4分钟目标。玩家还要面对对手发表、反击和棋子寿命。另须核实是否有真实功能性阻断（例如批次no_spawn_space、AI压制、卡池克制缺失、碰撞不感染）；尚不能把所有失败都归结为PK系数。

## 本次任务
1. 先对当前真实版本用1～2分钟短测记录每10秒 P/O/N、PK%、玩家发表及失败理由、感染成功数、当前三卡、对手发表与反击、人口空间；证明失败来自规则失衡还是核心动作失效。复用现有tracker或F3接口做最小数据采集。
2. 首先调整唯一来源的PK速度系数，让玩家获得稳定人口优势时PK可在目标时长内明显移动；2.0～3.0百分点/秒可作为待实测工程候选，不是最终批准数值。避免直接强制胜利或关闭对手；保证PK可以升降、有翻盘和2～4分钟正常对局目标。
3. 根据真实曲线才有针对性调节对手首次出手/发言间隔、领先2人即反击的门槛、反击CD及次数、补中立节奏和首关卡池属性分布。保留三种属性克制、2/4/8、50/60/70和玩家对落点的选择；数据表和运行时必须消费同一正式参数。
4. 试玩至少：一局不操作（能输）、两局普通操作、一局利用克制落点；后续关做两个短时状态检查。记录耗时、胜负、PK曲线与调整前后差异；首关必须存在不用F3的胜利路径。
5. F3和失败重开修复之后进行最终真人完整一局确认；未跑实机时只汇报参数候选，不声称已经调平衡。

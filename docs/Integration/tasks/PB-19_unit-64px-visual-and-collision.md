# PB-19 · 棋子显示与真实碰撞统一为 64×64

优先级：**P0｜正式战斗棋盘密度与接触体验调整**。Owner：**Lane D（显示）＋B（模拟与碰撞）＋A（合流）＋E（截图与交互验收）**。

状态：**2026-10-19 新确认策划变更**。此卡覆盖 [PB-16](PB-16_unit-portrait-visual-size-and-readability.md) 中 128×128 头像和半径 64px 的旧目标；#275/#281/#287 已有的有效实现作为修改起点。本任务卡不是已完成的代码。

## 已经实现的功能
- PB-15：开局 **30 名中立+2名对手种子**，随机补人中心间隔 0.75 秒±25%，预留完整发表批次的 8 人容量作为可调工程初值。
- 当前候选头像显示直径 **128 逻辑像素**、模拟碰撞半径 **64 逻辑像素**；B/E 已通过 127px/129px 接触与非接触的针对性验证。
- 最近实际截图证明128px头像在 1024×828 中央棋盘拥挤、上沿受到 HUD 遮挡，现确认缩小一半。

## 本次任务
### 1. 统一缩小到 64×64（D）
1. 棋盘内玩家、对手、中立棋子的**原始逻辑显示直径统一为64px**（64×64），以模拟圆心为头像、光圈、选中态、尾巴/动画的基点。
2. 维持正式原画比例，轮廓、头像与阵营提示清楚可辨；密度/compact 模式也以64px为基准，不再私自缩至其他固定大小。
3. 复核上/下安全区域，确保 PK/Tier HUD、局内状态文字、卡片操作区和头像不会互相压盖；与 PB-20 气泡避让并行但按各 Owner 文件划分改动范围。

### 2. 圆形碰撞直径也同步改到 64px（B）
1. 当前 Plan B 使用圆形模拟与 CircleShape2D；把真实**碰撞半径统一设为32逻辑像素**，圆外接框 **64×64**，不保留128px旧物理接触范围。
2. 同步核对碰撞接触/感染裁决、分离距离、同盟结团与脱离阈值、空间邻域检索、随机出生落点、棋盘四边界、点击/命中反馈和运动中心。
3. 用户仍要求 30 名中立+2对手、后续随机补人以及强度1/2/3一次发 **2/4/8** 颗。保持这些业务规则；参数若确需调整须以真实记录说明原因并交A按任务卡处理。
4. 按新的64px直径更新接触测试边界：例如**63px圆心距应触发接触/分离裁决，65px圆心距不触发接触**；参考实际 Godot 精度和当前接触条件对照检查。沿用已有感染概率/克制行为，不改玩法。
5. 团体、连线和气泡锚点都从同一模拟圆心读取，不因视觉改变而引发碰撞错位。

### 3. 一次联调与真实截图（A/E）
1. A 在已存在的 PB15/16 集成候选上统一应用 B/D 的变更，并按接口依赖做最小必要接触、随机补人和整批发表验证。
2. E 在实际 Godot 场景中记录 1280×720 和 1920×1080 的**30中立+2敌方开局**与接触画面，突出新64px棋子与 HUD/气泡空间；如有动态感染，仅补一次短片/目标场景日志。
3. 每个 Owner 独立提交可追溯的子任务 commit、日志和 PR；不要混入旧 128px 画面宣称本卡视觉 PASS。

## 验收标准
- 三阵营棋子的头像逻辑显示直径 **64px**，圆形碰撞半径 **32px**，图形中心与模拟中心一致。
- 30中立+2敌方正常生成/活动，63px接触、65px不接触的最小行为验证通过，感染/弹开、2/4/8以及棋盘边界继续生效。
- 真实 Godot 截图在 PR 正文可直接打开，并标注合流 SHA 和窗口分辨率，64px头像没有被 HUD、气泡、底部操作文字严重遮挡。

## Godot 开发环境
- Godot：**4.7.2**；语言：**GDScript**；项目根目录：`Empty-start/`；目标：Windows PC 优先，逻辑画布 1920×1080，并在实际 1280×720 窗口检验。
- Godot 工程操作 MCP：**Godot-MCP-Native**；Godot 官方文档 MCP：**godot_mcp**。

检查真实 main/目标基线、分支、worktree、未提交代码、场景树、节点、资源、信号和现有任务 PR；基于最新真实实现接续。

涉及字体测量、Control 尺寸、CanvasItem 绘制、物理形状等 API 差异时，按 godot_mcp 查官方 4.7.2 文档。
### 9. 使用 Godot-MCP-Native 检查真实工程

延用稳定 Resource、信号和公开接口，不制造跨场景深层 NodePath 耦合。

检查场景实例、继承、UID、owner 与信号连接，做局部改动并保留已工作的流程。

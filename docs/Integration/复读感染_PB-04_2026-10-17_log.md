生产组合接口：

- `bind_sources(battle_host, unit_source, word_catalog)`：A 负责 `get_pk()`、`publish_word("player", word_id, unit_id)`、`get_faction_counts()`、`get_unit_snapshots()` 与 `pk_changed(value)`；当 A 转发 `unit_changed/unit_spawned/unit_despawned` 时优先订阅 A，否则订阅 B。
- A 的 `tier_changed(current_tier)` 和 `battle_ended(result)` 驱动临时档位及结束提示。
- C 提供词条数组给 `set_word_definitions()`；战斗中遇到列表以外的 `word_id` 时，UI 通过 C 的 `get_word_definition(word_id)` 补读显示文本。
- 已发表列表及剩余冷却可由 A 调用 `set_published_word_ids()`、`set_publish_cooldown_remaining()`同步。成功发表回执会即时更新本地显示镜像；真正的发表合法性、冷却和顺序仍由 A 判定。
- UI 不生成棋子、不分配 `word_order`、不修改 PK 或阵营人数。失败时依据 A 返回的 `reason` 解释冷却、重复句和目标状态。

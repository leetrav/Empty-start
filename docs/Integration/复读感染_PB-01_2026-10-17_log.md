## A 的公开入口与调用顺序

### 生命周期与只读数据

- `start_battle(arena_size, arena_origin = Vector2.ZERO)`：重置本局，从 PK 50%、顺序号 1 和 Tier 0 开始；坐标原点供 B 场地和 D 棋盘映射使用。
- `pause_battle()` / `resume_battle()`：暂停或恢复模拟、PK 和自动发言。
- `restart_battle(arena_size)`：按新局规则重置。
- `end_battle(result)`：只发送一次结束事实。
- `get_pk()`、`get_faction_counts()`、`get_unit_snapshots()`、`get_current_tier()`、`get_word_definitions(team)`、`get_used_word_ids()`、`get_publish_cooldown_remaining(team)`：向界面提供只读事实。
- `publish_word(team, word_id, neutral_unit_id) -> {ok, reason, word_order?}`：玩家与费米共用入口，team 为 `player` 或 `opponent`。

### 发表事务

1. A 依次检查战斗状态、阵营、C 词定义、全局重复词、该阵营冷却，以及目标当前仍属中立。B 的 `unit_id` 为整数；C 和 D 当前入口传字符串 ID 时，A 按 B 的只读快照识别并转换。
2. A 暂取当前 `next_word_order`，调用 B 的 `seed_unit(neutral_unit_id: int, team: StringName, word_definition, candidate_order)`。
3. B 返回成功后，A 才记录已用词、提交该阵营冷却并递增全局顺序号。任何失败只返回 `reason`，不会占用词、冷却或顺序号。
4. B 发送 `unit_changed(unit_id: int, reason: StringName)`、`unit_spawned(unit_id: int)`、`unit_despawned(unit_id: int)` 事实；A 将 ID 和原因转换为字符串后转发，D 通过事件和只读快照刷新显示。
5. 正式模块接入时，A 通过 B 的 `set_play_area`、`create_population`、`start_simulation` 组装战斗；暂停/恢复走 B 的 `set_active`。C 的 `PlanBContentCatalog` 经 `load_test_configuration()` 初始化；C 的 `PlanBFermiOpponentDirector.configure(catalog, seed)` 接收同一词库。
6. A 每帧向 C 调用 `update_speech(delta, neutral_unit_snapshots, available_opponent_word_ids)`；C 发出 `publish_word_requested(word_id, neutral_unit_id)` 后，A 仍调用唯一的 `publish_word("opponent", ...)`。当前占位控制器按 3 秒首发、11.5 秒后续间隔运行；正式 C 间隔读取费米配置表。

### PK 与 Tier

- A 每帧读取 B 的 `get_faction_counts()`。速率为 `0.85 × (player - opponent) / total` 个 PK 百分点/秒，neutral 只进入总数分母。
- 人数相等时 PK 不变；seed、convert、relay 事件自身都不直接修改 PK。
- PK 为 0% 时发出 `battle_ended(&"failed")`，100% 时发出 `battle_ended(&"enter_contradiction")`。
- `pk_changed(value)` 仅在 PK 实际改变时发出，`value` 范围为 0～100。`tier_changed(current_tier)` 按现有 `data/combat_stage/tier_catalog.tres` 阈值更新，只作临时 T0～T5 可视读数。
- 玩家发表冷却为 5 秒；对手 A 层校验冷却为 11.5 秒。C 的对手请求时钟也读取费米配置。

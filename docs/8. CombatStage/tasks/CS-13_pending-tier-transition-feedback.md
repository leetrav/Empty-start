# CS-13 Tier 升降档清屏与震动反馈（需求暂存）

**状态：需求收集中 / 未完成 / 暂不派工**

> 本卡只记录策划要求的程序行为及尚未决定的细节；后续整理为正式 Agent 任务卡。本阶段不指定动效制作方式、节点结构、具体持续时间或代码实现。

## 已有能力
- 08 CombatStage 已支持 Tier 0～5、升档/降档、一次结算跨多档，以及当前 Tier 状态通知。
- 03 BarrageGeneration 管理实际弹幕生成与生命周期；战斗阶段、重开和矛盾阶段已有各自的清理流程。
- 现有 Tier 变化会改变新弹幕的生成倍率、速度、寿命、Neutral 权重、复读数量与对手回拉等参数。

## 已确认的新需求
1. **向上突破档位时短暂清屏。** 从 **T0 升至 T1** 时，弹幕场需要出现短暂清空，并配合一段明确表达“阶段突破”的转场动效。
2. **每次向更高 Tier 突破均有相应清屏反馈。** 不只 T0→T1，T1→T2、T2→T3 等上行阶段变化也应有清屏及突破演出。
3. **下行不按上行规则清屏。** 已明确示例为 **T1 降至 T0**：场上弹幕继续存在，不作升档式清屏；改为以**屏幕抖动**表达档位下降。
4. **升降档反馈与真实档位状态一致。** 动效用于表现档位变化，不改变已经计算出的 Tier 结果、PK 结算、话语原句身份或三项倾向；转场结束后仍继续正常战斗。
5. 本卡记录的是**程序触发、清屏与震动行为**；动效最终时长、强度及视觉内容后续再定。

## 待后续确认
1. 上行清屏的范围：普通话语、普通复读、矛盾及其他特殊实例是否全部包含；尚未逐类确认。
2. 清屏演出是瞬间移除并留出短暂空档，还是有短时过渡；具体清空时序和生成恢复时机。
3. T2→T1、T3→T2 等其他降档是否一律只震动、保留原有弹幕；目前直接确认的例子为 T1→T0。
4. 一次结算跳过多个 Tier 时，播放一次最终突破还是依次表现中间档位；重复升降同一档是否每次触发。
5. 屏幕抖动的作用范围、时长与幅度，以及是否影响输入/准心体验。
6. 清屏是否影响已排队尚未出现的复读及其统计，需结合 RP-13 和既有 10 号系统规则进一步讨论。
7. 特殊战斗阶段与神降临的 Tier 固定机制是否使用这些升降档反馈。

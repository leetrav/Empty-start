# BG-15 高密度动态弹幕与区域群体命中需求暂存

**状态：需求整理索引 · 已拆分正式任务卡 · 本卡保留历史设计依据**

已拆分单功能卡：**BG-16～BG-33**。各卡以各自触发条件及验收为实施依据。

> 本卡仅记录已讨论并确认的**游戏行为与验收目标**。后续仍会增补及调整，再拆分为独立、可直接交给 Agent 的正式开发任务卡。本文不规定节点类型、渲染方案、运动算法、性能优化手段或具体代码结构。

## 一、总目标

将目前较稀疏、主要从右向左横移的弹幕场，调整为**高密度、自由交叉、前后层级变化、随机运动与缩放的动态弹幕空间**。该系统在玩家视角中应有大量话语从各方向涌入、交错、穿透的效果，同时保持玩家在准心区域内一次命中多条弹幕的游戏行为。

视觉运动、前后覆盖属于表现层；弹幕的来源、原句、倾向、强度及游戏规则仍应保持正确。参考《如龙0》电话交友俱乐部中信息板交错运动的空间感，仅用于帮助描述交互和运动特征；具体弹幕美术外观由独立美术需求负责。

## 二、已确认需求

### 1. 高密度同屏弹幕
- 希望把目前几十条量级的同屏弹幕容量提升至**约 500～1000 条**。
- 500 与 1000 是本轮拟验证的目标档位，**最终稳定上限尚未确定**，应依据实际运行和性能测试决定。
- 需要验证 Godot 引擎在 PC 和 Android 实机上的实际表现；高密度下仍应保持战斗操作、弹幕运动和命中反馈可用。
- 压力测试应包含弹幕持续生成、运动、缩放、交叉覆盖、命中与消失等真实战斗情形，不能仅凭空场静态显示数量确定上限。

### 2. 全区域随机出生
- 弹幕可以从**战斗弹幕区域**四周任意位置进入，不局限于右侧。
- 弹幕也可以在**战斗弹幕区域内部的随机位置**直接出现。
- 出生位置与后续运动方向不再绑定为从右向左。
- 四周边缘出生与区域内部出生都属于正式需求；两种方式的出现比例暂未确定。

### 3. 四种运动方式
弹幕生成后应能够随机采用多种运动方式，首轮已确认包括：
1. **直线运动**：按方向移动、穿越场地；
2. **曲线运动**：沿弧线或其他弯曲路径移动；
3. **加减速运动**：运动中可以加速、减速，速度随时间变化；
4. **游荡运动**：在战斗区域中改变方向、持续游走。

四种运动方式的选取比例、具体速度区间、加速度、转向幅度与变化频率待后续讨论。不同运动效果可以使弹幕在场内相互穿行。

### 4. 交错、穿透与随机覆盖层级
- 弹幕可以相互**交叉、重叠、穿过**，出生与移动时允许共享屏幕空间。
- 同屏弹幕具有前后显示层级，**生成时随机确定层级，运动过程中层级也允许改变**。
- 前后覆盖是屏幕视觉表现，不代表某条弹幕在逻辑上被其他弹幕消除或失效。
- 弹幕即使被其他弹幕完全覆盖，仍保持正常的可命中资格；其自身特殊玩法特性仍按对应战斗规则判断。

### 5. 动态大小与速度
- 弹幕尺寸可以随机变化，包括出现后逐渐放大、缩小，以及运动过程中再次变化。
- 运动速度也可以动态变化，出现加速、减速等效果。
- 玩家看到的弹幕实际显示区域变化时，对应可被击中的区域也应与其显示尺寸一致。
- 动态尺寸、速度和层级变化只影响表现与空间命中位置，不直接更改话语原有倾向、强度、来源或原句身份。
- 随机缩放的幅度、变化频率、允许的最小/最大尺寸尚未确定。

### 6. 富文本及单句内部文字动画
每条弹幕的文本不仅需要整体运动，还希望支持**一句话内部的丰富表现**，两类能力均已确认需要：
- **混合文字样式**：同一句中的部分词语或字符能够使用不同颜色、字体、字号及强调样式；
- **局部动态文字效果**：关键词或局部字符能够抖动、闪烁、波动或变形。

具体哪些词触发、表现幅度、播放条件以及正式文字格式数据如何提供，后续再讨论。本卡不指定使用哪种 Godot 文本节点或其他渲染技术；实现方案应等性能验证后确定。

### 7. 准心覆盖区域内的群体命中
- 玩家的一发攻击覆盖到某片区域时，**该区域中所有实际满足命中条件的弹幕均视为命中**，即使它们彼此前后重叠、完全遮挡。
- 命中判断依据各条弹幕自身当时的实际显示范围与准心攻击范围的交集；**不按照最前层优先或只选肉眼可见的一条**。
- 单发可命中的弹幕**数量本身不设额外上限**，命中多少条就逐条保留多少条实际命中事实；特殊规则所规定的不可选中、异常结果等仍遵循对应系统。
- 所有实际命中目标仍应进入游戏当前适用的**真实结算**与相关统计，不因 PK 收益达到上限就把剩余命中从事实中删掉。复读、倾向、命中历史等后续效果应以真实有效命中记录为输入，并遵循各自系统原有规则。

### 8. 单发 PK 收益和惩罚分别封顶
- 为避免高密度叠加使 PK 数值失衡，需要对**同一发攻击造成的 PK 正向增加**和**PK 负向惩罚**分别设置可配置的上限。
- 即使本发实际命中几十或几百条弹幕，最终 PK 正收益不超过本发正向上限；负向惩罚不超过本发负向上限。
- **命中事实与 PK 限幅是两个概念**：对 PK 数值限幅不等于对命中条数、命中历史、复读或倾向变化统一限幅。
- 两个上限的具体数值、正负效果在同发中如何组合、异常特性结算边界，待结合第 06 命中结算系统进一步确认。

## 三、跨系统讨论边界（仅登记需求归属）
- **03 弹幕生成**：同屏数量、出生位置、运动模式、移动/缩放/层级、文本显示的承载和实际性能。
- **05 战斗攻击**：实际显示范围与准心的群体相交判定、单发实际命中目标集合。
- **06 命中结算**：同发所有有效目标的真实结算、PK 正向与负向分别封顶。
- **04 弹幕特性**：当前特殊特性的可选中与异常行为保持其既有规则。
- **10 复读 / 17 三项倾向及其他消费方**：继续消费真实有效命中事实，后续如有额外数值或性能规则另行讨论。
- **美术表现**：颜色、质感、半透明底板等外观要求另由程序美术需求维护；本卡只写文本能力和运动/命中行为。

## 四、待定事项
1. PC / Android 实机上的最低可接受帧率、性能分档以及最终稳定同屏上限。
2. 四周出生与内部随机出生的权重；四种运动模式的权重、运动范围及运动参数。
3. 尺寸随机区间、放缩变化的节奏、显示层级变化的频率。
4. 不同弹幕类别（普通、复读、矛盾等）是否共享全部运动与文本表现，以及分别适用哪些上限。
5. 富文本关键词、样式数据来源及局部动画触发规则。
6. 第 06 系统的单发正向 PK 上限、负向 PK 上限，以及异常效果和大量同发命中的组合结算细则。
7. 高密度实际命中造成大量复读或其他后续事件时，各系统是否需要独立性能策略；保持真实结算是已经确定的基础要求。

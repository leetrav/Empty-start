## 已经实现的功能与失败现象
- 顶部两侧主播名和 **❤粉丝团名❤** 为纯文字，现有评论系统可从正式评论行区分粉丝和路人。
- PR #317 的 `_create_fan_nameplate_row()` 用 `row_width = _comment_list.size.x`，继而用源图可见矩形的宽高比算 `row_height`，再将横牌 `STRETCH_SCALE` 填满整行，并把“用户名：评论正文”压进横牌内 `(0.34, 0.12)-(0.96, 0.88)` 区域。
- **用户实机截图不通过**：左右出现巨大、抢眼的粉丝横幅，像广告牌一样挤占评论栏；ID 与正文缩在绿色牌面上，文字浅/糊、换行别扭，不如普通评论清楚。作为连续刷新的直播评论，密度和层级均不合适。

## 本次任务
1. **还原评论信息层级**：主播资料顶部继续仅显示“主播名 + ❤粉丝团名❤”。粉丝徽章和横向身份牌仅作为评论列表里**单条粉丝评论 ID 的局部装饰**，整个列表仍以可连续阅读的 `ID：评论正文` 为主。
2. **缩小横牌，不再撑满评论区**：以昵称部分的实际安全区计算受限宽度和高度，使其接近普通评论的文字行高。徽章完整置于横牌圆形安全区，等比不变形；横牌的内圆与名字文本实际对齐。普通评论的总行高与粉丝评论相近，长评论可自然增加正文高度。
3. **ID 和正文分区**：将粉丝牌负责的昵称身份与正常评论正文区分布局；评论正文使用现有易读字号、对比度与换行，确保普通读者能快速扫读。长 ID 应合理截断/省略或在身份区换行，正文始终完整可读；局部尺寸不足时通过稳定布局处理，而不是整体缩至难以辨认的 12px。
4. **修复评论列表节奏**：粉丝与路人混排时滚动、可见行数和间距保持稳定；主侧/敌侧都沿用所属角色的正式牌与徽章，角色变化后正确同步。检查 1280×720 与 1920×1080 的实际场景。
5. **视觉对比**：参考用户失败截图中的绿色大牌（左下方、右下方），输出同位置的修复后对比图。确保粉丝评论不再独占过大的垂直面积、压迫底部评论和影响棋盘、主播区信息。

## 修复验收标准（真实 Godot）
- 1920×1080 整屏与 1280×720 整屏中，粉丝牌是**评论区单条小型身份标识**，视觉重量显著低于直播间主播立绘和主要操作卡牌；不会占据评论栏一大块面积。
- 单条评论中：徽章完整可见、横牌不变形、用户名在牌内、正文在正常背景上易读；短 ID、长 ID、两行评论、粉丝与路人混排均看得清。
- 实际滚动列表可展示多条信息；左右双方使用对应主播的颜色和素材；顶部保留 **❤粉丝团名❤**，不出现大号粉丝牌。

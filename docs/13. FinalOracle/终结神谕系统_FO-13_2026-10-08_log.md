## 3. 当前数据所有权

- `FinalOracleSession` 拥有冻结候选快照；正文只从当前 `LevelProfile.normal_speech_pool` 按稳定 ID 解析并补入深拷贝。正文缺失时报错，不显示原句 ID。
- `FinalOracleCandidateDisplay` 只管理 Label 和目标到原句 ID 的显示映射。
- `AttackChargeInput` 拥有本发攻击阶段、目标快照及选择命中事实；FinalOracle 选择模式不调用 HitResolution。
- `HitResolution` 仍唯一拥有玩家 PK 和本场普通命中历史；Repeat 仍拥有复读统计；`FinalOracleConfirmationState` 仍按当前 `SaveData + level_id` 限定一次确认。

## 4. 真实调用链与场景接线

```text
CB 成功与静音过渡结束
→ Sandbox 创建 FinalOracleSession 并冻结候选
→ FinalOracleCandidateDisplay 在 BattleArea 显示原句
→ Sandbox 将 Label Control 注入 AttackChargeInput
→ 普通攻击释放时冻结候选 ID 与准心中心
→ 到达时复核目标；多目标只选中心距准心最近的一句
→ selection_target_hit → Sandbox → Session.confirm_display_candidate()
```

- `FinalOracleSelectionTimer.expired` 时，Sandbox 调用 `select_timeout_candidate()`；手动命中和超时均进入 `_confirm_oracle_candidate()`。
- 进入神谕时显式停止普通弹幕生成、清场并停止对手回拉。确认后停表、清除攻击目标、停止攻击输入；PK、Tier、倾向和复读统计不因选择攻击变化。
- `final_oracle_opened(session)` 保留为阶段事实通知。正式候选表现使用 BattleArea 中的独立显示组件。
- Agent B 无需补做 Sandbox 接线；场景中只新增了一个 BattleArea 子场景实例。

## 本次任务

把 FinalOracle 的选择方式改成“主游戏区内用普通攻击击中候选”。

不再使用独立全屏 Panel、候选卡片或点击按钮作为玩家选择方式。

## 目标流程

```text
矛盾击破成功
→ 矛盾复读展示结束
→ 静音过渡
→ 保留原战斗界面
→ 中央主游戏区出现 1～3 条固定神谕候选
→ 玩家移动准心、蓄力、发射
→ 命中其中一句
→ 该句成为本场最终神谕
```

## 1. 展示位置

候选直接显示在当前中央 PK 主游戏区。

左右主播、PK Bar、Tier、直播数据和现有战斗 HUD 继续保留。

FinalOracle 不切换到独立全屏页面。

候选当前固定不移动。

本卡只做固定候选；后续候选生成方式、移动方式和特殊表现等待新的需求。

## 2. 候选显示

每条候选只显示真实话语正文。

不显示：

- 正统 / 异端 / 荒谬标签；
- 候选 1 / 2 / 3；
- “选择这句话”；
- Panel 卡片；
- 点击按钮。

候选展示快照必须包含可显示的真实原句文本。

不得把 `original_sentence_id` 当成玩家可见正文。

可以沿稳定 `original_sentence_id` 从当前关卡真实话语数据解析正文，或在进入 FinalOracle 时形成包含正文的冻结展示快照。

## 3. 玩家操作

完全复用普通攻击操作：

```text
移动准心
→ 按住蓄力
→ 蓄满
→ 松开发射
→ 命中候选
```

不要增加点击候选、直接鼠标选择等第二套操作。

进入 FinalOracle 后：

- 普通弹幕生成保持停止；
- 对手 PK 回拉保持停止；
- PK 保持冻结；
- 不产生普通战斗 PK / 倾向 / 复读收益；
- 攻击只用于选择 FinalOracle 候选。

## 4. 同一发命中多个候选

布局优先让 1～3 条候选彼此保持足够距离，降低一发覆盖多条的概率。

如果同一发实际命中两条或更多候选：

```text
计算各候选中心到当前准心中心的距离
→ 取距离最近的一句
→ 只确认这一句
```

同一发只产生一次正式神谕确认。

## 5. 10 秒超时

保留现有 10 秒倒计时。

候选已经出现在主游戏区并允许玩家操作后才开始计时。

全局暂停时继续沿用现有规则冻结倒计时。

10 秒结束且玩家尚未确认时，继续使用 FO-08 的正式自动选择顺序：

```text
普通复读次数
→ 最近命中
→ 原句 ID
```

超时自动选择与玩家攻击命中共用 FO-09 的同一个最终确认入口。

## 6. 单次确认

继续使用现有：

```text
当前 SaveData + level_id
```

作为同一场提交身份。

玩家攻击命中与超时自动选择都只能正式确认一次。

首次确认后：

- 当前候选不再接受新的选择；
- 选择计时停止；
- 后续流程继续读取同一份正式确认结果。

## 7. 现有 FinalOracleScreen

当前 Panel + Button 交互表现退出正式玩家流程。

可以复用其中已经存在且适合继续使用的：

- 10 秒计时逻辑；
- timeout 逻辑；
- confirmation 逻辑。

玩家最终交互必须发生在中央主游戏区。

如果该 Scene / 脚本在修改后没有真实消费者，清理对应死代码或无用节点。

## 8. 0 候选

本卡不新增 0 候选兜底流程。

当前设计保证进入 FinalOracle 时存在有效非 neutral 候选；Tier 5 的 neutral 普通话语生成权重为 0。

## 验收

- 矛盾击破成功后不再弹出独立 FinalOracle Panel。
- 原战斗 HUD 保持可见。
- 中央主游戏区显示 1～3 条固定候选。
- 玩家可使用原准心、蓄力、发射流程完成选择。
- 候选只显示真实话语正文。
- 命中一条后只确认该条。
- 同发命中多条时只确认离准心中心最近的一条。
- 选择期间 PK、回拉和普通弹幕保持冻结。
- 10 秒倒计时正常工作，暂停时冻结。
- 超时自动选择继续使用 FO-08 正式排序。
- 手动攻击命中与超时自动选择继续共用 FO-09 单次确认入口。
- Godot 4.7.2 实际运行完整 `CB 成功 → FinalOracle → 手动命中确认` 流程无新增错误。

## 测试

本卡不新增单元测试。

- 手动攻击命中；

- 10 秒超时自动确认；

- 确认后不能再次提交。

## 已经实现的功能
- 正式身份为 12 张；现有 GridContainer **4 列**、卡框 **280×350**，有逐张翻牌、一键翻开、选中、高亮、下一步、返回与身份数据传递。
- 身份卡美术为十二张独立卡面、统一卡背；当前第二轮修复将文字放在卡图下部纸面板，但 **1280×720 仍只能看到第一排与下一排上沿**。
- 第三排最长说明和正式完整流程仍未完成实际视觉验收。

## 本次任务
### 1. 所有身份卡必须在同一屏幕完整展示
1. 在 **1920×1080** 和 **1280×720** 实际窗口里，12 张身份卡都无需纵向/横向滚动即可完整看到并点击。推荐 **6 列×2 行**的网格总览；若现有布局有更稳定的等效方案，可采用同样满足 12 张全可见的方案。
2. 保持原卡图宽高比约 **0.80（297×371）**；头像/图案、卡背、边框与焦点一致随布局自适应。根据**当前可用页面尺寸**计算卡片大小与间距，避免沿用固定 280×350 导致溢出。
3. 每张缩略卡至少清楚显示图案和身份名称，完整卡背/翻面状态仍可识别；调整文字大小和内容布局时优先保证图案可辨。使用已有 GridContainer、Control 与动态布局即可。
4. 页面标题、12 张卡、完整说明区和确认/返回操作都必须处于同屏可操作范围。页面空间优先留给总览，长文另设阅读位置。

### 2. 选中后在固定说明区阅读完整身份文案
1. 点击或键盘聚焦某张卡后，固定详情区显示该身份的**完整名称、正式描述和选中态**；不需要把最长 33 字全文缩小塞在每一张缩略卡里。
2. 全文保留当前身份配置数据；按详情容器实际可用宽度自动换行，文字与背景有足够对比度，不能截字或把内容挤出页面。
3. 维持单张翻面、一键翻面、选择、取消/改选、下一步、返回和最终身份保存。当前身份 ID 到暂定卡图的映射不因布局而改变。
4. 键盘焦点/鼠标操作可触达全部 12 张卡；选中高亮与详情区同步，背景装饰不能覆盖文字。

### 3. 最小视觉验收
1. Godot 真正打开身份选择页，记录 **1920×1080 与 1280×720**：两张截图都必须同时看到完整十二卡、详情区域与导航按钮。
2. 选中含最长正式文案的身份，再记录一张完整说明截图；验证翻开和确认可执行。缩略图上不要求展示全文，详情中必须完整可读。
3. 对比当前 #286 的 4 列滚动版，将新图嵌入 PR 正文；小于 1280×720 的极端窗口可按现有规则降级，但须明确说明实际行为。

## 验收标准
- 1920×1080 与 1280×720 **12/12 卡同屏、无滚动即可逐张操作**，保留身份数据/翻牌/确认流程。
- 一张含最长原文的身份选中时完整内容可读、边框/图案无拉伸，不遮挡操作按钮。
- PR 正文附上述真实 Godot 截图、分辨率与 SHA；A 检查和美术 #271、布局 #282/#286 的依赖合流无覆盖。

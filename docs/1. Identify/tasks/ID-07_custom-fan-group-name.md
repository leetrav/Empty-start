## 本次任务
只补充“玩家在开局可以自定义粉丝团名，并让这个名字随本周目保存”这一项能力。

完成后的开局身份设置页面同时包含：
- 主播名输入框；
- 粉丝团名输入框；
- 身份选项；
- 确认按钮。

粉丝团名使用与主播名一致的名称确认方式：
- 玩家填写实际内容时，保存玩家填写的粉丝团名；
- 输入为空白时，使用身份系统集中配置的默认粉丝团名；
- 默认粉丝团名放在明确、可修改的位置，方便策划之后替换文案。

实现时优先复用 ID-02 已有的名称确认逻辑。若现有实现只接受“主播名”语义，则把它整理成可复用于主播名和粉丝团名的最小公共名称确认逻辑。

将最终粉丝团名加入当前周目数据，字段使用稳定、直观的名称，例如：

```gdscript
fan_group_name
```

身份设置确认后，同一次提交得到：
- 最终主播名；
- 最终粉丝团名；
- 已确认身份 ID。

现有 SaveManager 继续负责保存和读取这三个结果。

### 验收条件
- 身份设置页面可以输入粉丝团名。
- 正常输入会作为本周目的粉丝团名保存。
- 空白输入会得到集中配置的默认粉丝团名。
- SaveData 中存在粉丝团名字段。
- 保存并重新读取后，粉丝团名保持一致。
- 当前关卡重开继续读取同一周目的粉丝团名。
- 主播名、粉丝团名、身份 ID 在一次身份确认流程中一起进入当前周目数据。
- 已有主播名与身份选择行为保持原有结果。

### 本任务测试约束
- 优先复用 ID-02 已有的名称确认测试。
- 同一套“空白回退 / 正常输入保留”规则同时服务主播名和粉丝团名时，沿用现有 2 个关键测试即可。
- UI、SaveData 字段和实际保存读取使用最小 Godot 运行验证。

先确认 ID-02、ID-04、ID-05、ID-06 的真实代码、场景、字段和公开接口，再基于现有实现补充粉丝团名。

### 2. 保持当前职责

### 3. 复用现有名称规则
主播名和粉丝团名共享相同的输入清理与默认值回退规则。已有逻辑满足需求时直接复用；需要泛化时只调整当前实际使用到的最小部分。

在现有身份设置页面增加粉丝团名输入控件，并沿用当前 Theme、布局方式、确认流程和信号连接方式。

### 5. 保持存档方向一致
在现有 SaveData 中增加粉丝团名字段，由当前 SaveManager 的 new/save/load 流程统一管理。

### 6. 使用真实 Godot API
涉及 LineEdit、Resource、SaveData、场景节点或信号时，先检查项目现状；对 Godot 4.7.2 API 有疑问时查询 godot_mcp。

### 7. 验证

- GDScript 正常解析；
- 身份设置场景正常加载；

- 自定义粉丝团名可以保存并读取；
- 进入游戏后当前 SaveData 中同时存在主播名、粉丝团名和身份 ID；
